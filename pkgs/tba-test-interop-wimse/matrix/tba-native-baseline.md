# All-TbA workload and support baseline

The [TbA peer record](../src/tba_test_interop_wimse/peers.toml) tracks native readiness for every entity role in [hops.toml](../src/tba_test_interop_wimse/hops.toml). An all-TbA flow uses one implementation record and separately configured participants. For example, TbA workloads A, B, and C have separate identities and keys. B receives A's request and initiates its own request to C. A credential, token, or policy service has its own participant ID when its operation is a separate hop.

The peer record uses four readiness values. **Interop-qualified** refers to a workload role with peer lab evidence. **Local fixture** means the test package has exercised the role in a lab scenario. **Components** means TbA has reusable code and still needs the deployed role wired and qualified. **Planned** means the role still needs an implementation for this matrix.

## Matrix and runtime changes

1. Add an explicit all-TbA pairing mode in `matrix.py` and carry it through `hop_expansion.py` and `__main__.py`. For each arrow, match the source and destination roles, profiles, issuer and identifier options, then keep each participant's assigned identity and implementation consistent across the flow. Give native runs their own qualification and execution records.
2. Register the native endpoint and support factories in `tests/peer/conftest.py`. Extend `tests/support/typed_workload_chain.py` to resolve the two ends independently and accept an exact TbA-to-TbA pin. Add typed runtime bindings for credential acquisition, delegation, token exchange, and status or policy checks.
3. Qualify each applicable directional binding and each issuer or support role using separate identities and effect state. Start with one successful and one refused call for every native workload profile, then exercise two- and three-hop flows. Run the full constrained native inventory and audit per-ID outcomes, including the reached hop, decision hop, and protected effects.
4. Use the same role contracts when substituting one qualified external implementation into a native flow. SPIFFE and WIMSE packages remain independently usable, and a combined profile explicitly composes its transport and application proof.
